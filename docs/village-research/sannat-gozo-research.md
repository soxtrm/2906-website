## Name, administration and editorial boundary

Use the official Maltese name **Ta' Sannat** in titles and first mention, with **Sannat** where an operator's own naming requires it. The Local Council places the locality in southern Gozo, extending towards the Ta' Ċenċ cliffs, with Munxar to the west and Xewkija to the east. Keep the village distinct from Munxar, Xewkija, Victoria, Xlendi and the wider south-Gozo coast.

The council page is the administration source. Visit Gozo supplies visitor and heritage context. Neither establishes a particular street, square position, view, gradient, parking arrangement, nearest stop, walking route or access condition for the current listing.

## Current source-check result

Visit Gozo's Ta' Sannat page, Malta Public Transport Route 305 and the filtered MTA restaurant register returned HTTP 200 by direct request on 23 October 2026. Ta' Sannat Local Council and Primary HealthCare rejected the direct command-line client with HTTP 403; their current browser-readable records were used only for the limited administration and clinic statements above. The five MTA identifiers and names were present in the returned filtered HTML. The four Commons candidates were checked through their exact file pages and Wikimedia API metadata. The complete originals of candidates 1 and 3 were downloaded and visually reviewed; candidate 1 was selected and a documented 1800px WebP derivative was created.

The private `sannat-gozo-preview.html` now keeps village core, Ta' Ċenċ, Ħanżira valley and Mġarr ix-Xini separate, uses `noindex,nofollow`, has no canonical or initial iframe, and creates its OpenStreetMap locality view only after a click. Static parsing found one H1, one 1800×1350 hero, zero initial iframes and no residual Il-Qala route or asset labels; the configured OSM embed returned HTTP 200. Exact object-fit simulations at 390×360 and 1440×580 were visually inspected; the desktop focus was raised to retain both tower tops while the mobile crop keeps the full façade legible.

The real preview was subsequently checked in Chromium at 390×844 and 1440×1000. Both viewports had zero horizontal overflow, one H1, `noindex,nofollow`, no canonical, no initial iframe, a fully loaded 1800×1350 hero and visible BrandyMay / Wikimedia Commons / CC BY-SA 4.0 attribution. The map action creates exactly one titled iframe, hides the button and sets the status message. The redundant lazy-loading hint was changed to eager loading because the iframe is already created only after explicit consent; this made the mobile OSM canvas render reliably. Mobile and desktop screenshots showed the locality map, and all 10 mobile and 28 desktop OSM responses observed during the final run succeeded. The click handler is one-shot, so a repeated dispatched click does not create a second map. No public HTML, sitemap, index, live deployment, backlink or external post was created in this step.
