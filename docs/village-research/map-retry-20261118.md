# Deferred map dependency recovery

Confirmed on 18 November 2026: after the first Leaflet stylesheet request fails but its script loads, a subsequent map request sees `window.L` and skips the stylesheet. The API appears successful while Leaflet panes have `position: static` and the map is not correctly styled. If the script fails instead, the rejected shared dependency promise remains cached. This is a controlled network-failure reproduction, not a claim that all live maps were broken.

The loader now shares a complete script-and-stylesheet attempt, removes its failed injected elements and clears the failed promise so a later requested map can retry. A successful script is reused on that retry, while the stylesheet is still required. There is no background retry loop, scheduler, route change or new tile preloading.

Browser recovery results are in `map-retry-browser-20261118.json`: CSS and script failures separately at 390 and 1440 pixels, followed by successful recovery and computed absolute map-pane positioning (4/4). Before the patch, the stylesheet-failure reproduction issued only one stylesheet request and the second map remained unstyled (2/2 widths). Scripts and original results remain under `artifacts/20261118-map-retry`.

Normal local browser flows passed at 360/390/430/768/1440: deferred OSM loading, real raster tiles, touch/hover church label, places filtering, honest local-homes output and edition search. Screenshots wait for the second map's raster images; the 390px screenshot was visually checked. SEO/sitemap/accessibility contract passed for 81 editions; all three route/ferry regression files passed. Production publication has not yet been verified by this document's source commit.
