## 2. Gaps against the brief

- **No owner account or session.** Owners only hold capability tokens (upload 90 days, schedule, NEXUS invitation).
- **No recurring weekly availability, buffers, notice, exceptions or holidays** in ARGUS; windows are single dated ranges (max 8 h) or a "viewings from" date; slots 10/20 min only.
- **No two-stage confirmation.** Owner accept → `confirmed` directly; no agent/client reconfirmation.
- **Owner schedule page:** one property, 7 fixed days, no decline reason or counter-proposal, no confirmed list, saved times not shown or removable.
- **No delegates / property managers, no pilot states, no owner audit trail, no notification digest.**
- **Commission/referral data does not exist** in the CRM (only `created_by`).

## 3. Security findings (outside this feature, to fix first)

1. **Owner-upload token accepted as a staff session (high, verify on production).** `auth()` in `routes/crm.js` (snapshot :147-166) refuses only `aud==='board'`; the owner-upload token is `jwt.sign({ownerContactId, aud:'owner-upload'}, JWT_SECRET, 90d)` (:2592). Routes without a live-agent check (e.g. `GET /owners` :2128) would accept it. Fix: accept only `aud==='crm'` (or legacy no-aud with numeric `id`); separate secret for owner tokens. Filed as a separate task.
2. **Next → backend over plain HTTP to a raw IP** (`http://178.104.162.193:3001` in every proxy). Sessions and PII cross the internet unencrypted; `/owner-upload` calls it from an HTTPS page (mixed content, likely broken).
3. **`GET /owners/:id` returns WhatsApp `chat_id`s** (effectively phone numbers), bypassing masking and the reveal limit.
4. **Owner documents are permanent public Cloudinary URLs.**
5. **The owner schedule page shows the agent's note and the client profile** to the owner.
6. **NEXUS invitation stays readable after it was consumed** until expiry.

The new portal avoids all of these by construction (own secret, hashed revocable sessions, allow-listed projections, SQL-scoped queries) — but it does **not** fix them.

## 4. UI shell findings (Phase D)

- No `viewport-fit=cover` in `app/crm/layout.tsx` → every `env(safe-area-inset-*)` is 0 on iOS; the island sits on the home indicator.
- Breakpoints disagree (639 / 760 / 761 / 640 px); 640–760 px shows the island over desktop layouts.
- Custom dialogs without `data-state` do not trigger the island shrink rule; toasts at z 90 sit under the island (z 100).
- `transform`/`will-change` on `.crm-board-islands` / `.crm-mobile-island-panel` clip fixed children; sheets use `vh` not `dvh`.
- Wheel scrolling only inside `.crm-content` (fix on branch `claude/crm-wheel-scroll-anywhere`, `ba3d745`).
- No standalone ARGUS "A" control; the orbit search button and wordmark are the brand assets.

## 5. Plan (this branch: `claude/argus-owner-portal`)

Backend slice `ops/owner-portal/backend` (additive migration, own routers, tested on a local Postgres 16 with a stub of the touched core tables; **re-run against the production schema dump before deploy**):

- `owner_portal_accounts`, `owner_portal_invitations` (hash only), `owner_portal_sessions` (hash only, revocable, 30 days), `owner_portal_delegates` (property manager: listed properties × scopes), `owner_portal_audit`.
- `owner_viewing_rules` (per property) → materialised `property_viewing_windows` rows.
- `owner_property_proposals` (owner edits → staff review; never written to `properties` directly; agent-owned commercial terms excluded).
- `viewing_coordination` (+ events): the REQUESTED → OWNER_SLOT_PROPOSED → AGENT_CLIENT_CONFIRMATION_PENDING → CONFIRMED machine, holding time through `property_viewings`.
- `owner_share_links` (agent-facing, allow-listed fields, revocable, never a login).
- `owner_pilot_states` (Interested → Pilot invited → Onboarding → Active pilot → Feedback received).
- `owner_distribution_settings` (sync destinations and states; MVP: existing ARGUS agency only, others "not connected").

Frontend: `/owner` portal (mobile-first: properties, property editor, weekly calendar, request desk with drag-and-drop + tap-to-assign), `/property-link/[token]` agent page, staff controls on the owner profile.

Not in the MVP: WhatsApp delivery (gateway not enabled for owners), notification digests (stored preference only), NEXUS/partner destinations, fees (never charged; terms are data only).
